# 市场页格子规范（Widget Spec）v1

> 终局形态：市场页 = 固定底座格 + **问答生成的动态格**。
> 核心约束：格子内容由原语组合表达，LLM 只填内容、不碰样式；
> 前端唯一的 `renderWidget(payload)` 负责一切渲染。

---

## 1. 设计原则

1. **等大网格**：2 列，行内严格等高（min-height 300px，`grid-auto-rows:1fr`）。
2. **五段壳**：所有格子（固定与动态）共用同一壳结构，只有"体"里的原语不同。
3. **原语有限集**：体 = `answer + metrics + rows + stage + table + chart` 六种原语的
   合法组合（见 §3）。规范外一律拒绝渲染。
4. **答案先行**：每个格子必须能用一个词 + 一句话回答"它解决什么问题"。
5. **颜色语义固定**：good=红涨/bad=绿跌/warn=琥珀留意/flat=灰中性/blue=信息。
   LLM 只能选 tone，不能给色值。

## 2. 壳规范（固定，不可配置）

```
┌────────────────────────────────────────────┐
│ [标题14px·700] [pill·tone·一词结论] [数据龄]   …操作链 │  ← 壳头 42px
│ 一句话答案（answer，13px，最多 60 字）              │  ← 答案行
│  · 原语区（2~6 个原语，见 §3）                    │  ← 体
│ 口径：source（11px 灰）                           │  ← 壳脚
└────────────────────────────────────────────┘
```

- **操作链**（固定格）：看依据 → / 问 XX 分析师 → / 看全部 N →。
- **操作链**（动态格）：`重跑`（重新问一次）· `删除`。
- 数据龄超过 1 个交易日自动转琥珀并提示"偏旧"。

## 3. 原语清单（六种，格子的全部词汇）

### 3.1 metric —— 大数指标（2~6 个，网格排布）
```json
{ "k": "近 5 日涨跌", "v": "-3.2%", "s": "相对板块 -1.1%", "dir": "dn" }
```
约束：`k` ≤ 6 字；`v` 为数值型字符串（渲染用 mono）；`dir ∈ up|dn|null`；
`s` 可空，≤ 14 字。

### 3.2 row —— 明细行（0~6 行）
```json
{ "left": "贵州茅台", "note": "资金偏出 · 放量", "right": "-2.1%", "dir": "dn" }
```
约束：`left` 主名 ≤ 8 字；`note` 灰注 ≤ 16 字；`right` 数值；行数 > 4 时
第 5 行起折叠为"还有 N 行"。

### 3.3 stage —— 阶段轴（仅情绪/周期类，一格最多一条）
```json
{ "kind": "emotion", "on": 1 }
```
档位固定：冰点/修复/发酵/高潮/退潮。`on` 为下标。其他周期（如库存周期）
须先在规范中登记档位，禁止临场造档。

### 3.4 table —— 迷你表（仅多标的对比，一格最多一张）
```json
{ "head": ["", "1 日", "3 日", "5 日", "方向"],
  "rows": [["宁德时代", "+0.89", "+4.28", "+11.81", "转入"]] }
```
约束：2~4 数值列、≤ 6 行；首列是名，末列可放一词方向。

### 3.5 chart —— 迷你图（可选，一格最多一条）
```json
{ "kind": "spark|bars", "data": [12, 15, 11, 18], "dir": "up" }
```
`data` 4~24 个数值，只画形状不标轴；读数靠 metrics。

### 3.6 pill（壳内复用，不算体原语）
```json
{ "tone": "warn", "text": "钱在出" }
```

## 4. Payload 规范（renderWidget 的唯一入参）

```json
{
  "id": "w_20261120_1730_a1b2",
  "kind": "auto",                  // fixed | auto（问答生成）
  "title": "白酒板块",              // ≤ 8 字
  "pill": { "tone": "warn", "text": "钱在出" },   // 一词结论，必填
  "age": "11-20",
  "answer": "板块资金连出 4 日，估值回到 5 年 30% 分位，先等钱稳。",  // ≤ 60 字，必填
  "metrics": [ /* 3.1，0~6 */ ],
  "rows":    [ /* 3.2，0~6 */ ],
  "stage":   null,
  "table":   null,
  "chart":   null,
  "source":  "问：白酒板块怎么样 · 资金流分析师 · 11-20 15:41",
  "question": "白酒板块现在怎么样",   // auto 格必填：生成该格的原始问题
  "ttl_days": 5                     // 过期天数，默认 5
}
```

**硬校验**（后端 + 前端双重）：
- `pill` 与 `answer` 必填；体至少含一种原语；
- 原语字段越界（字数/行数/档位）→ 截断并标 `truncated: true`，不报错不拒收；
- tone/dir 只能取枚举值，非法值回落 flat/null。

## 5. 固定格子清单（11 格，每格一行的规范）

| 格 | 回答的问题 | 体 = 原语组合 | 数据源 | 生成方式 |
|---|---|---|---|---|
| 今天的结论 | 今天什么状态，该定什么调子 | answer + metrics×3（钱/国家队/情绪 mini）+ rows×2（怎么做、距改判） | 汇总三路 | 固定渲染 |
| 市场资金 | 钱进没进 | metrics×3（成交/宽基/两融）+ metrics×4（新钱/旧钱/活跃度/在撤）+ chart(spark) | fund tab | 固定渲染 |
| 国家队 | 托不托、撤不撤 | metrics×3（托市/份额/在撤）+ rows×4（出手日/压力位/当日净申购/份额） | team tab | 固定渲染 |
| 情绪 | 市场在哪个阶段 | metrics×6（趋势/强度/主线/宽度/情绪/量）+ stage | mood tab | 固定渲染 |
| 板块·在攻/在出 | 机会和危险在哪些板块 | rows×4（双榜各 2） | sectors | 固定渲染 |
| 板块·关注与启动 | 今天盯什么 | rows×3（今日关注）+ rows×2（启动/退） | sectors | 固定渲染 |
| 个股资金流 | 我的票钱进钱出 | table（自选 1/3/5 日） | fetch_flow_compare 同源 | 固定渲染 |
| 热闻 | 市场在聊什么 | rows×6（热榜） | hot-news | 固定渲染 |
| 宏观 | 大位置在哪 | rows×3（分项）+ rows×1（外部） | macro | 固定渲染 |
| 日历 | 接下来有什么事 | rows×4 | calendar | 固定渲染 |
| 外盘 | 隔夜环境 | rows×6（指数） | overseas | 固定渲染 |

## 6. 问答生成格子链路（auto 格）

```
用户在问问提问（如"白酒板块怎么样"）
   ↓ 主理人照常编排（请板块/资金流分析师）
分析师 reply 正常直播
   ↓ 回合结束，主理人判定"这是一个可沉淀的看板问题"
调用 emit_widget 工具（参数 = §4 payload，参数 schema 即本规范）
   ↓ 服务端校验 + 落库（按 user_id 隔离）
市场页出现新格子（排在 11 个固定格之后，"我的看板"区）
```

规则：
1. **谁生成**：主理人（不是维度分析师）在回合结束调用 `emit_widget`，
   内容从分析师正文与工具数据中提炼——分析师保持"答问"，主理人负责"沉淀"。
2. **同题更新**：`question` 归一化后 hash 作幂等键，重问 = 原地更新数据龄，
   不新增格子。
3. **上限**：每用户 6 个 auto 格，满 6 提示替换最旧（或让用户点选替换谁）。
4. **生命周期**：`ttl_days` 过期标琥珀"偏旧"，用户可一键重跑（服务端带着原
   `question` 重新走一遍编排）或删除。
5. **入口反馈**：问问页分析师答完且已生成格子时，答案尾部出现一行轻提示：
   "已加到市场页看板 · 查看 →"。
6. **二期（活数据）**：auto 格接调度器按 ttl 自动重跑，替代手动"重跑"。

## 7. 与现有代码的衔接点

- 渲染：`renderWidget(payload)` 一个函数吃所有格子；固定格把现有渲染函数
  （hero/macroCard/…）的输出**适配成 payload**，过渡期允许双轨。
- 存储：auto 格随个人数据走（`internal/personal`，X-User-Id 隔离），
  与持仓/想买同库。
- 工具：`emit_widget` 注册进问问主理人工具集（`registerSessionTools`），
  描述里附本规范 §4 的字段约束。
- 多票资金对比（`fetch_flow_compare`）天然产出 table 原语——第一个
  auto 格的天然场景。
